# UI/UX Design Guideline: Minimalistic AI Interface

This document serves as the absolute source of truth for the visual style and component architecture of the AI interface. All code generated by Claude Code must strictly adhere to these principles to maintain a clean, distraction-free user experience.

---

## 1. Visual Principles & Constraints

*   **Whitespace-First:** Layouts must feel open. Do not fill screen real estate with unnecessary boxes or borders. Use padding and margin to group related elements.
*   **Monochromatic & Accent:** The primary interface relies entirely on a neutral grayscale palette (pure whites, deep grays, blacks). Use exactly **one** vibrant accent color solely for active states, primary actions, or critical system feedback.
*   **Contextual Reveal:** Never render settings, sliders, or secondary action buttons by default. UI elements must only appear contextually when triggered by user intent or specific AI outputs (Generative UI).
*   **Typography over Icons:** Rely on strong typographic hierarchy (font weight and size scaling) instead of custom icons to distinguish content types.

## 3. Core Component Layout Rules

### Main Chat Window / Canvas
*   Centered layout with a maximum readable content width (`max-w-3xl` / approx. 768px).
*   No visible borders separating the chat history from the background canvas.
*   Transitions between messages must use a subtle fade-in (`duration-200 ease-out`).

### The Smart Input Bar (The Centerpiece)
*   **Idle State:** A simple, single-line input field anchored at the bottom. Background uses `--bg-surface` with a soft, natural drop shadow (`shadow-sm`).
*   **Active State:** Expands vertically based on content up to a strict maximum height. Focus ring switches to `--accent` border with `0` outline.
*   **Buttons:** Action icons (e.g., attach, submit) only show opacity change on hover. No colored button fills unless the input contains text ready to submit.

### AI Output Formatting (Markdown Elements)
*   **Paragraphs:** Line-height must be generous (`leading-relaxed` / 1.625) to ensure legibility.
*   **Code Blocks:** Dark background regardless of system theme (`#1E1E2E` or similar dark slate). Monospaced font without custom styling borders.
*   **Lists:** Inline bullets or numbers must match `--text-muted` to stay visually secondary to the text itself.

---

## 4. Animation & Micro-Interactions

*   **AI Streaming/Typing:** Do not use aggressive pulsing animations. A subtle horizontal layout shift or a simple fading cursor element at the end of the text stream is preferred.
*   **Button Hovers:** Scale down transitions (`transform scale-98`) instead of aggressive color changes to make clicks feel tactile but quiet.
*   **Page Transitions:** Avoid hard page refreshes. Content must morph seamlessly into place.

---

## 5. Implementation Checklist for Generated Code

Before finalizing any UI components or views, ensure compliance with these rules:
- [ ] No borders used where padding or margin could separate elements instead.
- [ ] No more than two distinct font sizes visible within a single text block.
- [ ] No traditional multi-level navigation sidebar present (use an overlay drawer or command menu instead).
- [ ] Accessibility (Contrast ratio of text against background satisfies WCAG AA standards).
